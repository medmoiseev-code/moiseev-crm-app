# Moiseev Admin CRM — версия 0.2

Отдельное браузерное приложение для работы администраторов. Интерфейс и поля повторяют лист «Пациенты Моисеев» примерно на 90%.

## Что уже есть

- выбор сотрудника без пароля: Елизавета, Виктория, Глеб, Федор;
- роли: администратор и руководитель;
- рабочая таблица с теми же основными колонками;
- отдельные комментарии врача и администратора;
- неизменяемая история карточки пациента;
- несколько телефонов и несколько врачей;
- любое количество независимых задач у одного пациента;
- отдельные обзвоны, профосмотры, приёмы и напоминания;
- быстрые даты: завтра, через 3 дня, неделю, полгода;
- отчётность только для Глеба и Федора;
- полный JSON-бэкап и восстановление.

## Запуск

После клонирования создайте локальный файл начальных данных из безопасного пустого шаблона:

```bash
cp src/imported-data.example.js src/imported-data.js
```

В Windows PowerShell:

```powershell
Copy-Item src/imported-data.example.js src/imported-data.js
```

Файл `src/imported-data.js` исключён из Git. Не добавляйте в репозиторий реальные персональные или медицинские данные пациентов.

```bash
npm install
npm run dev
```

После запуска откройте адрес, который покажет Vite.

## Хранение данных на текущем этапе

Данные сохраняются в `localStorage` браузера. Поэтому:

1. Регулярно нажимайте «Скачать бэкап».
2. Для переноса на другой компьютер используйте «Восстановить».
3. До реальной эксплуатации на нескольких компьютерах нужно подключить общую облачную базу.

## Будущее подключение StomX

В карточке пациента предусмотрен будущий внешний `stomx_id`. После получения API задачи и пациенты смогут синхронизироваться без изменения пользовательского интерфейса.

## Серверный учёт рабочего времени

Для общего учёта смен и расчёта зарплаты выполните `supabase/schema.sql` в Supabase SQL Editor и заполните локальный `.env`:

```env
VITE_SUPABASE_URL=https://ВАШ-ПРОЕКТ.supabase.co
VITE_SUPABASE_ANON_KEY=ВАШ_ANON_KEY
```

После подключения смены, запросы исправлений, ставки и журнал корректировок сохраняются в Supabase. Локальный ключ `moiseev_worktime_offline_v01` используется только как офлайн-кэш и очередь синхронизации. До настройки Supabase учёт времени работает локально для проверки интерфейса, но не должен использоваться как постоянная зарплатная база.

Перед эксплуатацией необходимо заменить временный выбор пользователя полноценным Supabase Auth и включить RLS-политики: администратор должен иметь доступ только к своим сменам, руководитель — ко всем сменам, ставкам и запросам.
