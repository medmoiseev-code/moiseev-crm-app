# Axio SRM — демонстрационная версия

Демонстрационное браузерное CRM-приложение на Vite. В проект включены только вымышленные пациенты, несуществующие телефоны и тестовые медицинские сведения.

> В демонстрационной версии данные сохраняются локально в браузере и не синхронизируются между компьютерами.

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Vite покажет локальный адрес приложения. Изменения рабочих данных сохраняются в `localStorage`. Исходный демонстрационный набор можно восстановить через меню пользователя → «Сбросить демоданные». Настройки темы и интерфейса при этом сохраняются.

## Проверка production-сборки

```bash
npm run build
npm run preview
```

Готовые файлы создаются в каталоге `dist`. Конфигурация `vercel.json` сначала обслуживает существующие статические файлы, а остальные адреса перенаправляет на `index.html`, поэтому прямое открытие SPA-адресов не приводит к ошибке 404.

## Публикация на Vercel

1. Создайте новый репозиторий на GitHub.
2. Загрузите в него текущее чистое содержимое проекта **без истории старого репозитория**. Не публикуйте прежнюю Git-историю, поскольку в ней мог присутствовать удалённый файл импорта пациентов.
3. Войдите в [Vercel](https://vercel.com/).
4. Нажмите **Add New → Project**.
5. Импортируйте созданный GitHub-репозиторий.
6. Убедитесь, что Vercel определил фреймворк **Vite**.
7. Укажите **Build Command**: `npm run build`.
8. Укажите **Output Directory**: `dist`.
9. Нажмите **Deploy**.
10. После завершения Vercel покажет публичную ссылку на приложение.

Установка Node.js посетителям не требуется: браузер загружает уже собранные статические файлы.

## Публикация последующих изменений

Зафиксируйте изменения и отправьте их в ветку GitHub, подключённую к Vercel:

```bash
git add .
git commit -m "Описание изменений"
git push
```

Vercel автоматически создаст новую сборку и обновит публичную версию. Для других веток и pull request Vercel может создавать отдельные preview-ссылки.

## Данные и безопасность

- Начальные данные генерируются в `src/initial-data.js` и являются полностью демонстрационными.
- Изменения не перезаписываются при обновлении страницы и остаются только в текущем браузере.
- Сброс демоданных восстанавливает пациентов, задачи, лист ожидания и историю, не меняя пользовательскую тему.
- Файлы `.env`, выгрузки, CSV, Excel, бэкапы и импорты пациентов исключены из Git.
- Не добавляйте реальные данные пациентов, пароли, токены и API-ключи в репозиторий.
- Для демоверсии база данных не используется.

Удаление файла из текущего состояния Git не удаляет его из прежних коммитов. Для публичной демоверсии используйте новый репозиторий с новой историей либо предварительно очистите историю специализированным инструментом. Не отправляйте старую историю в публичный GitHub-репозиторий.

Если позже будет подключён Supabase, создайте локальный `.env` по образцу `.env.example`. Не коммитьте этот файл и не помещайте секретные значения непосредственно в исходный код.
